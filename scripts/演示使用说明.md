# 演示库与演示服务器

演示人物为小夏与阿远，全部内容虚构。共 450 条记忆：知识 150、印象 130、对话 110、事件 40、日记 20；均匀分布在最近 60 个本地日期内，每天 7～8 条，最后几条为今天。角色卡 792 字。图谱包含 451 个节点（含角色核心）、1,266 条关联，最高度数 19，独立记忆节点 50 个。

10 个主要主题团各有 8～12 条记忆；26 个团词各出现在 6～8 条记忆中，没有跨团使用。原评分器的 DF 上限是 9，出现 9 次仍保留，10 次会被过滤。同一条记忆里重复一个词只算一份文档。咖啡团的 8 条记忆内部连通，共 24 条内部连线，对外连线为 0。其余为 300 条日常关联内容和 50 条孤岛。

团词使用自然措辞，并通过标题中的完整词片段让原评分器识别；仅把词埋进长句不保证成为候选关键词。生成器调用原评分器核对实际连线，没有改动 DF 公式或渲染参数。

## 开始录制

在插件目录打开终端，执行：

```powershell
node scripts/demo-server.mjs
```

浏览器打开 <http://127.0.0.1:8899/memory-engine/>，按 F11 全屏。图谱、记忆、设置三个页签复用插件现有界面，无需打开 DSH。点金色核心查看角色卡，点普通节点查看详情和关联线；记忆页可搜索“咖啡”、切换分类、选择“快忘了”排序，也可编辑、删除、导出和清空演示记忆。

录完在启动服务器的终端按 Ctrl+C。端口被占时可换端口：

```powershell
node scripts/demo-server.mjs --port 8900
```

如果本机提示找不到 `node`，使用 DSH 自带的运行环境：

```powershell
$nodeExe = Join-Path $env:USERPROFILE '.dsh\dsh-runtimes\dsh-primary-runtime\dependencies\node\bin\node.exe'
& $nodeExe scripts/demo-server.mjs
```

下文命令中的 `node` 也可以换成 `& $nodeExe`。

## 数据位置与重新生成

数据目录是当前用户文档目录下的 `deepseek-harness/default-workspace/qq-setup/state/_demo/`：

| 文件 | 用途 |
| --- | --- |
| `source.json` | 虚构内容源文件；在这里调整记忆内容 |
| `cluster-plan.json` | 主题团规模、团词、计划 DF 与分配表 |
| `roles/小夏.md` | 虚构角色卡 |
| `home/.dsh/memory-engine/memories.json` | 页面实际读写的演示库 |
| `home/.dsh/memory-engine/config.json` | 演示配置，自动记忆和自动导入均关闭 |
| `generated/starmap.html` | 可直接打开的离线图谱 |
| `generated/index.html` | 服务器页面外壳，需要通过服务器打开 |
| `generated/demo-*.png` | 浏览器验收截图 |
| `generated/browser-checks.json` | 浏览器验收记录 |
| `generated/cluster-audit.md` | 每个团词的计划与实际 DF、团内及对外连线表 |
| `generated/structure.json` | 原评分器和实际图谱的结构验收结果 |
| `generated/verification.json` | 全量测试、浏览器、隐私、真实库与原模块未变的最终验收记录 |
| `generated/tests.txt` | 195 项测试的完整结果 |

修改 `source.json` 或角色卡后，在插件目录运行：

```powershell
node scripts/generate-demo.mjs
```

这会先核对团词 DF、分类数量、孤岛及连线指标，再按当前日期重新生成库、HTML 和结构核对报告，并将页面中的临时修改恢复为源文件内容。已有演示库会先备份，沿用原存储模块的备份保留和原子写机制。刷新页面即可使用新数据。修改源文件时保留分类总数、`cluster` 与 `island` 标记；不符合结构约束时，生成器会报出原因，不覆盖当前库。

配置以相对路径 `roles/小夏.md` 指定角色卡，同时保存同步的 `personaText`，供原渲染模块读取；修改角色卡后必须重新生成。设置页故意显示公开目录名 `demo/home/.dsh/memory-engine`，避免录屏暴露 Windows 用户名。导出、备份提示也使用该公开名称，实际文件仍在上述 `_demo` 目录。

## 隔离与验收

服务器只监听本机，保留 Host 校验。数据写入限定在演示目录，拒绝目录链接、文件链接和路径重定向；页面脚本全部在本地，不依赖 CDN。所有管理接口调用原路由与原存储模块，`lib/` 没有修改。

已通过：

- 175 项插件测试 + 12 项已有演示测试 + 8 项扩容测试，共 195 项全部通过，无失败、无跳过。新增验证涵盖规模、团词 DF、跨团约束、连线、枢纽、孤岛、9/10 次过滤边界和整个演示目录的隐私扫描。
- 18 项浏览器检查：三个页签、五类节点、金色角色核心、动画、角色详情、节点详情及关联线、搜索、排序、设置目录与条数、导出、编辑、删除、清空与空库引导，并核对扩容后的规模、连线、孤岛与枢纽；重新生成图谱、记忆、设置、搜索、角色卡五张截图，另有节点连线截图。
- 演示目录内所有 JSON、Markdown、HTML 均通过任务书禁词检查。
- 整轮扩容及演示读写前后，真实库的哈希、字节数、修改时间与条数保持一致，真实库中演示记录仍为 0；`lib/` 全部文件哈希未变。验证程序只读对照真实库，演示服务器不读取真实库。
- 在进程无权读取真实库、只能写入演示目录的情况下，页面接口及清空操作仍正常。

复跑完整测试：

```powershell
node --test --test-concurrency=1 --test-reporter=tap test/*.test.mjs scripts/demo-server.test.mjs
```

串行运行可避免图谱生成与旧的 50 毫秒性能断言争用资源；并行首跑曾出现该断言耗时 55 毫秒，其余检查通过，没有修改原测试阈值。浏览器验收需要 Edge 和正在运行的默认端口服务器：

```powershell
node scripts/demo/check-browser.mjs
```

浏览器验收会实际编辑、删除和清空演示数据，结束时从源文件恢复 450 条。它只操作演示站。单独的离线 HTML 仅提供图谱；录制三个页签请使用服务器地址。
